# Политика данных и приватности

Единый документ, фиксирующий, какие данные архива являются публичными, какие доступны после семейного входа, а какие никогда не покидают сервер. Основан на решениях владельца проекта (раздел 12 плана).

## Слои доступа

| Слой | Кому доступен | Где живёт |
|---|---|---|
| Публичный | Любой посетитель сайта без входа | Ответы `public.*` Apps Script + статика GitHub Pages |
| Семейный | Держатели общего семейного пароля (действующая сессия) | Ответы `private.*` только после серверной проверки токена |
| Служебный | Только владелец Apps Script / редакторы Google | Закрытая Google Sheet, проектная папка Drive, Script Properties |

## Матрица полей

| Данные | Публично | После входа | Никогда в frontend без авторизации |
|---|---|---|---|
| `personId`, ФИО, год рождения и год смерти | Да | Да | — |
| Ветвь, поколение, родительские и брачные связи | Да | Да | — |
| Публичный аватар или нейтральная заглушка живого | Да | Да | — |
| Публичная биография умершего (`publicBio`) | Да (по умолчанию) | Да | — |
| Точные даты и места умершего в публичных полях | Да (по умолчанию) | Да | — |
| Биография живого (`familyBio`) | Нет | Да | Да |
| Точная дата и место рождения живого | Нет | Да | Да |
| Контакты, адреса, личные заметки (`familyContacts`, `familyNotes`) | Нет | Только эти разрешённые поля | Да |
| Карточка умершего с явным `detailsVisibility=FAMILY` | Нет | Да | Да |
| Публичные фотографии и документы | Да | Да | — |
| Приватные фотографии, их названия, подписи, метаданные | Нет | Да | Да |
| Внутренний `driveFileId` приватного файла | Нет | Нет (frontend получает содержимое по `mediaId`) | Да |
| Пароль, его хеш, соль, Script Properties | Нет | Нет | Да |
| Сырые строки Sheets, отчёты об ошибках с содержимым | Нет | Нет | Да |

## Правила

1. **Умершие публичны по умолчанию.** `isLiving=false` делает публичные поля подробной карточки общедоступными автоматически. Исключение — явное `detailsVisibility=FAMILY` в записи человека.
2. **Живые всегда защищены.** `isLiving=true` запрещает публичную подробную карточку, даже если редактор ошибочно выбрал `PUBLIC`: серверная проверка сильнее поля.
3. **Согласованность дат.** Наличие `deathDate` должно согласовываться с `isLiving`; смерть раньше рождения отбраковывается валидацией.
4. **Allowlist, а не blacklist.** Публичный сериализатор строит ответ из списка разрешённых полей; удаление «опасных» полей из полной строки не используется.
5. **Префикс `family` не публикуется автоматически.** Поля `familyBio`, `familyBirthPlace`, `familyContacts`, `familyNotes`, `familyCaption`, `familyDescription` недоступны публично даже для умерших.
6. **`includePrivate=true` и подобные параметры игнорируются.** Права меняет только валидная серверная сессия.
7. **Приватность фильтруется на всех endpoint.** Семейные события и медиа исключаются из `public.timeline`, `public.gallery`, карточек людей и материалов — везде, а не только в карточке человека.
8. **Объединение по `personId` в памяти браузера.** Приватный ответ содержит только дополнительные поля и `personId`; клиент объединяет его с уже загруженной публичной записью после успешной авторизации.
9. **Очистка после выхода.** После logout, отзыва или инвалидации сессии приватные Map/объекты, DOM, Blob URL отзывают (`URL.revokeObjectURL`), незавершённые запросы отменяются (`AbortController`).
10. **Фильтрация интерфейса — не защита.** Скрытие элементов в UI не считается механизмом защиты; защиту обеспечивает сервер.

## Публичные медиа

- `PUBLIC_ASSET` — локальные SVG-заглушки в `public/assets/`, публикуются сайтом.
- `EXTERNAL` + `visibility=PUBLIC` — внешняя HTTPS-ссылка, публикуется как есть.
- `DRIVE` + `visibility=PUBLIC` — файл проектного Drive, открытый по ссылке; публикуется ссылка чтения. Приватный файл нельзя переводить в режим «доступно всем по ссылке» — это обошло бы защиту.

## Семейные медиа

- `DRIVE` + `visibility=FAMILY`: клиент передаёт только `mediaId`; сервер проверяет сессию, видимость и связь, читает файл из Drive и возвращает байты (base64) в POST-ответе; браузер создаёт Blob и временный Object URL и отзывает его после закрытия.
- `EXTERNAL` + `visibility=FAMILY`: ссылка выдаётся API только после входа. Внешний сервис не считается надёжной защитой: важные материалы хранятся в проектном Drive.

## Сессия

- Один общий семейный пароль; персональные аккаунты не создаются.
- Токен ≥256 бит; в Script Properties хранится только SHA-256-хеш токена, дата создания и `AUTH_EPOCH`.
- Автоматического TTL нет: сессия живёт до logout, смены пароля (рост `AUTH_EPOCH`), глобального отзыва или очистки данных браузера.
- В `localStorage` (ключ `familyArchive.token`) хранится только токен. Приватные данные, биографии, события, медиа и Object URL — только в памяти текущей страницы.
- Cache API и Service Worker для приватных данных не используются.
- На общем устройстве пользователь обязан нажимать «Завершить семейный режим»: закрытие браузера сессию не отзывает.

## Редакторы Google

Доступ редактора к закрытой Google Sheet и проектной папке Drive — это доверие к содержимому архива: семейный пароль сайта не разграничивает права внутри Google. Доступ выдаётся только доверенным родственникам; выдача и отзыв — штатными средствами Google.
