# Модель угроз

Фиксация активов, противников, принятых рисков и ограничений платформы. Ссылки на решения — разделы 2, 3, 5 и 10 плана `plans/astro-family-archive-plan.md`.

## Активы

1. Семейные биографии живых, точные даты/места, контакты, заметки (`family*`-поля Sheets).
2. Приватные фотографии и документы в проектной папке Google Drive.
3. Семейный пароль (точнее — его хеш и соль в Script Properties).
4. Действующие сессии (хеши токенов в Script Properties).
5. Доступность публичного сайта и API.
6. Целостность генеалогических данных.

## Ограничения платформы (принятые)

1. **Apps Script не управляет HTTP-статусами и произвольными заголовками** `TextOutput`; транспортный статус почти всегда 200. Используются прикладные коды в JSON (`error.status`). Реальные 401/403/429 и гарантированный `Cache-Control: no-store` потребуют HTTP-proxy (например, Cloudflare Worker) — отдельное архитектурное решение, не вносится скрыто.
2. **`ContentService` отдаёт контент через redirect** на `script.googleusercontent.com`. Поведение CORS проверяется прототипом (этап 1) с реального origin GitHub Pages в Chromium/Firefox/WebKit до массового переноса frontend.
3. **Нет надёжного IP клиента** в событии Web App → per-IP rate limit невозможен; защита глобальная и по идентификатору установки (он не секрет). Риск DoS входа принят.
4. **`no-cors`, JSONP и секреты во frontend запрещены**; CORS не считается авторизацией.
5. **Base64 приватных медиа** увеличивает ответ ~на 33%; рекомендованный размер — оптимизированные превью 2–3 МБ, жёсткий предел задаётся после тестов (базово 8 МБ).
6. **Квоты Apps Script/Drive** ограничены: пакетное чтение Sheets, публичный кэш, пагинация, мониторинг длительности.

## Границы защиты

- Публичность имён, лет жизни и положения в древе всех опубликованных людей — **принятая политика**, не уязвимость.
- Публичность публичных полей умерших по умолчанию — принятая политика; исключение — явное `FAMILY`.
- Семейный пароль не разграничивает права редакторов Google (см. `docs/data-policy.md`).
- Владелец Web App должен быть постоянным архивным аккаунтом: смена владельца требует повторного развёртывания.
