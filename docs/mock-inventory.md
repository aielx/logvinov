# Инвентаризация макета `family-archive-mock/`

Фиксация функций статического макета, которые переносятся в Astro-версию, и механизмов, которые переносятся быть не могут. Исходный mock остаётся в репозитории как визуальный эталон и не входит в production-сборку.

## Страницы

| Страница | Файл | Содержание |
|---|---|---|
| Лендинг | `family-archive-mock/index.html` | Hero, интро, превью древа (3 поколения, статичное), превью хронологии, превью галереи, блок «О проекте», футер |
| Древо | `family-archive-mock/tree.html` | D3-древо, тулбар (zoom, виды, фильтр ветвей), список, боковая карточка, логин-диалог |
| Хронология | `family-archive-mock/timeline.html` | Вертикальная лента событий, легенда «семья/история» |
| Галерея | `family-archive-mock/gallery.html` | Сетка материалов, фильтры категорий, лайтбокс |

## Данные макета

- **10 человек, 4 поколения** — `family-archive-mock/js/tree.js:1` (`mockData`): `id`, имя, годы `birth`/`death`, `fatherId`/`motherId`/`spouseId`, `generation`, `bio`, `photo`, `branch` (`common|ivan|peter`), `isPublic`.
- **11 событий хронологии** — `family-archive-mock/js/tree.js:144` (`mockTimeline`): `date`, `sortDate`, `title`, `description`, `type` (`family|history`), `icon` (буква маркера).
- **8 материалов галереи** — `family-archive-mock/js/tree.js:158` (`mockGallery`): `src` (SVG-заглушка), `title`, `date`, `category` (`archive|documents|portraits`), `categoryLabel`, `alt`.
- Живые родственники: `id=8` (Алексей, 1975–) и `id=10` (Дмитрий, 1978–), `isPublic=false`.
- 12 SVG-заглушек в `family-archive-mock/assets/` (портреты и архивные материалы).

## Функциональность, переносимая в новую версию

1. Общая навигация из четырёх страниц, мобильное меню (Escape, `aria-expanded`), sticky-хедер.
2. D3-древо: узлы-«аватары» с кольцом (цвет различает предков и живых), связи родитель–ребёнок, пунктирные брачные связи, подписи «имя / годы / пометка приватности».
3. Zoom (колесо, кнопки, `scaleExtent 0.25–3`), drag холста, сброс масштаба, `dblclick.zoom` отключён.
4. Фильтр ветвей (`all|ivan|peter`, ветвь `common` видна всегда), счётчик «N из 10 человек» с `aria-live`.
5. Вид «Список»: группировка по поколениям, сортировка по году рождения, клик открывает карточку.
6. Боковая карточка (dialog до 640 px): фото, поколение, годы, статус, биография, разделы «Родители/Супруг(а)/Дети» с кнопками-переходами, «Связанные материалы» (сетка 4 шт.).
7. Приватность в UI: `canView()` — подробная карточка живого только в семейном режиме; метки «ДЕТАЛИ ПО ПАРОЛЮ» / «СЕМЕЙНАЯ КАРТОЧКА».
8. Логин-диалог: нативный `<dialog>`, ошибка пароля с `aria-invalid`, toast-уведомления (`role=status`).
9. Событие `family:privacychange` — перерисовка древа и карточек при смене режима.
10. Хронология: чередование сторон, маркеры-буквы, цветовое различение `family|history`.
11. Галерея: фильтры с `aria-pressed`, счётчик склонений («материал/материала/материалов»), лайтбокс с подписью.
12. Доступность: skip-link, `focus-visible`, `visually-hidden`, возврат фокуса на закрытие, `prefers-reduced-motion` (отключение анимаций и smooth scroll), `dialog-open` (блокировка прокрутки).
13. Адаптивность: breakpoints 1050 / 760 / 480 px; на мобильных древо 68dvh, список в одну колонку.
14. Контакты: разработчик Александр Сергеевич Логвинов, `logvinovaleksander@gmail.com` (запрос доступа, участие).

## Механизмы, которые НЕ переносятся

| Механизм макета | Причина | Замена |
|---|---|---|
| Пароль `семья2025` в клиенте (`family-archive-mock/js/app.js:89`) | Пароль и проверка видны в исходнике | Серверная проверка в Apps Script, хеш+соль в Script Properties |
| Признак входа `sessionStorage.familyArchivePrivate` (boolean) | Не является авторизацией | Токен ≥256 бит в `localStorage`, серверные сессии в Script Properties |
| Приватные биографии живых внутри `mockData` | Доступны в JS-файле без входа | `private.person` только после проверки сессии; публичный API отдаёт allowlist-поля |
| `tree.js` со всеми данными подключается на всех страницах | Лишний вес и утечка данных | Данные — только через API; D3 — только на странице древа, из npm-сборки |
| D3 с CDN jsdelivr (`tree.html:13`) | Внешняя зависимость, ошибка «нужен доступ к CDN» | `d3` из npm в сборке; ошибка CDN невозможна |
| Рендер через неэкранированный `innerHTML` (`app.js:143`, `app.js:162`) | XSS при реальных данных | `textContent`, безопасное создание DOM, allowlist URL |
| Подсказка «Для демонстрации: семья2025» в форме | Публикует пароль | Убирается; серверная проверка |
| `buildGraph()` только по `fatherId` от корня `id=1` + один супруг (`tree.js:305`) | Не поддерживает двух родителей, несколько корней, компоненты, циклы | Нормализованная модель `Relationships` + новый построитель графа с валидацией |

## Архитектурное ограничение построителя древа

Текущий `buildGraph()`:

- строит одну иерархию `d3.hierarchy` от человека `id=1`, спускаясь только по `fatherId`;
- добавляет по одному супругу смещением `spouseOffset=130`;
- связь «родитель–ребёнок» рисуется от узла родителя (со сдвигом на половину `spouseOffset`, если есть супруг).

Требования к новому построителю (`src/lib/tree/build-graph.ts`):

- оба родителя (`PARENT_CHILD` в обе стороны);
- несколько корней и несвязанные компоненты;
- `SPOUSE` — одна запись на пару, без дублирующей обратной строки;
- отсутствующие данные (нет дат, нет родителей) не ломают построение;
- проверка self-loop, дублей связей, циклов `PARENT_CHILD`, несуществующих ID;
- вычисление поколений и выявление противоречий;
- фильтр ветви сохраняет общих предков и необходимые связи.
