# Резервное копирование и восстановление

## Что защищаем

| Актив | Чем копируем | Периодичность |
|---|---|---|
| Google Sheet (все данные архива) | Копия таблицы в закрытую резервную папку Drive | Еженедельно + перед каждой миграцией схемы |
| Drive-медиа (проектная папка) | Google Takeout или зеркальная копия папки | Еженедельно |
| Внешние медиа | Не контролируются проектом — важные материалы дублируются в проектный Drive | по мере добавления |
| Код Apps Script | Git-репозиторий (`apps-script/`) | каждый коммит |
| Код сайта | Git-репозиторий | каждый коммит |

Резервные файлы **никогда** не выгружаются в GitHub и не попадают в Actions artifacts.

## Автоматическая еженедельная копия Sheet [ручной шаг установки]

В редакторе Apps Script один раз создайте триггер «Время дня → Еженедельно» на функцию:

```ts
function weeklyBackup() {
  const source = SpreadsheetApp.getActive();
  const backupFolder = DriveApp.getFolderById("REPLACE_BACKUP_FOLDER_ID"); // закрытая резервная папка
  const stamp = Utilities.formatDate(new Date(), "GMT", "yyyy-MM-dd");
  DriveApp.getFileById(source.getId()).makeCopy(`Архив ${stamp}`, backupFolder);
}
```

(Функцию можно добавить отдельным файлом в проект Apps Script; в репозиторий она не входит, чтобы не хранить ID папок.)

## Восстановление (проверять на отдельной тестовой копии)

1. Открыть резервную копию Sheet, при необходимости **Файл → Создать копию**.
2. Если восстанавливается в новую таблицу: привязать новый Apps Script по `docs/deployment.md` (шаги 1–3), выполнить `setup()`, задать пароль, развернуть Web App заново.
3. Сверить `schemaVersion` копии с кодом; при миграциях — пройти их по одной.
4. Drive-медиа: скопировать файлы обратно в проектную папку; `driveFileId` сохраняются за файлами при копировании внутри одного аккаунта, при переносе между аккаунтами — обновить `sourceUrl` и выполнить «Заполнить недостающие ID».
5. «Проверить данные» → «Обновить публичный кэш» → smoke-прогон `prototype/api-smoke.html`.
6. Восстановление затрагивает пароль/сессии: Script Properties нового проекта чистые — задайте пароль и сообщите родственникам.

## Проверка восстановления

Раз в квартал: восстановить копию в тестовую таблицу + тестовое развёртывание `/dev`, проверить `health`, публичные разделы и вход. Результат фиксируйте датой в этом файле.
