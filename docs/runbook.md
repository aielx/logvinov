# Эксплуатационный регламент (runbook)

Типовые ситуации и порядок действий. Всё, что отмечено [ручной шаг], выполняет владелец в Google/редакторе Apps Script.

## Обновление семейных данных (ежедневно, редакторы)

1. Правки в Google Sheet / Drive штатными средствами.
2. Меню «Проверить данные» → исправить строки из «Отчёта проверки».
3. Изменения появляются на сайте ≤5 минут; срочно — меню «Обновить публичный кэш».

## Сайт не показывает свежие данные

1. Меню «Обновить публичный кэш» (dataRevision++).
2. Не помогло → «Проверить данные»: возможно, строки отбракованы валидацией.
3. Проверить Web App: `GET <exec>?action=health` — ответ `ok` с текущей `dataRevision`.
4. health падает → см. «API недоступен».

## API недоступен (сайт жив, разделы показывают ошибку)

Это ожидаемое поведение: статические страницы и навигация работают без API.

1. [ручной шаг] Консоль Apps Script → Executions: смотреть ошибки выполнения.
2. Проверить квоты/лимиты на день (UrlFetch здесь не используется; основные лимиты — триггеры и время выполнения).
3. Если менялся код — проверить, что развёртывание указывает на актуальную версию.
4. Долгий инцидент → назначить предыдущую версию развёртывания (откат API).

## Забыт/утёк семейный пароль

```js
setFamilyPasswordAndRevoke("новая-фраза")   // в редакторе Apps Script
```
Все сессии отзовутся автоматически. Новую фразу передать родственникам защищённым каналом.

## Нужно выгнать всех, не меняя пароль

```js
revokeAllSessions()   // в редакторе Apps Script
```

## Скомпрометирован приватный файл Drive

1. Переместить файл в карантин (удалить из проектной папки) — ссылка перестаёт открываться.
2. Очистить строку в `Media` (`status = DRAFT`, убрать `sourceUrl`).
3. «Обновить публичный кэш»; попросить родственников перезайти при необходимости.

## Ошибки валидации после массовой правки

1. «Проверить данные» → вкладка «Отчёт проверки».
2. Частые коды:
   - `PERSON_LIVING_WITH_DEATH` — у живого указана дата смерти;
   - `PERSON_DIED_BEFORE_BIRTH` — перепутаны даты;
   - `REL_CYCLE` — цикл поколений (замыкающее ребро исключено);
   - `REL_IMPLAUSIBLE_AGE` — родитель младше ребёнка < 13 лет;
   - `MEDIA_UNSAFE_URL` — внешняя ссылка не https;
   - `PERSON_AVATAR_PRIVATE` — аватар не публичный (заменён заглушкой).
3. Исправить строки, повторить проверку.

## Откат сайта

1. GitHub → Actions: перезапустить workflow прошлого зелёного commit **или** `git revert` problematic commit + push в `main`.
2. Проверить production URL и `/tree/`, `/timeline/`, `/gallery/`.

## Откат API

[ручной шаг] Редактор Apps Script → Развернуть → Управление развёртываниями → Изменить → выбрать предыдущую версию. Затем меню «Обновить публичный кэш».

## Ротация владельца аккаунта

Смена владельца Web App требует повторного развёртывания — см. `docs/deployment.md` шаги 1–5. Держите Apps Script и резервные копии за постоянным архивным аккаунтом.

## Мониторинг (минимальный)

- Раз в месяц: `GET action=health`, вход тестовым паролем не выполнять (счётчик попыток).
- Раз в месяц: число активных сессий (аномальный рост = утёкший пароль).
- После каждого деплоя: чек-лист готовности из плана (раздел 11).
