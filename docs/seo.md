# Поисковая оптимизация (SEO) и оптимизация для ИИ-агентов

Что уже сделано в репозитории и что нужно сделать руками, чтобы сайт находили
по запросам про род и фамилию Логвиновых.

## Что реализовано в коде

### Техническая база

- **Карта сайта**: интеграция `@astrojs/sitemap` (`astro.config.mjs`) генерирует
  `sitemap-index.xml` + `sitemap-0.xml` при каждой сборке. Канонические URL —
  со слэшем на конце (`/tree/`), как отдаёт GitHub Pages.
- **robots.txt** (`public/robots.txt`): разрешает индексацию всем краулерам,
  включая роботов ИИ-ассистентов, и ссылается на карту сайта.
- **Канонические URL** на каждой странице (`<link rel="canonical">`).
- **404 закрыта от индексации** (`noindex, nofollow`), остальные страницы —
  `index, follow, max-image-preview:large`.

### Соцсети и мессенджеры

- **Open Graph** и **Twitter Card** на всех страницах: заголовок, описание,
  картинка-превью. Картинка `public/assets/og-image.png` (1200×630) в фирменном
  стиле; перегенерация: `npm run gen:og` (нужен ImageMagick; шрифты скачаются
  автоматически).
- **apple-touch-icon.png** — иконка для закладок на iOS.

### Structured data (JSON-LD)

Через `src/lib/seo.ts` на страницах размещены машинно-читаемые данные:

- `WebSite` — название, язык, хранитель архива (publisher);
- `AboutPage` на главной, `CollectionPage` у галереи, `WebPage` у остальных;
- `ItemList` — разделы архива;
- `FAQPage` — вопросы-ответы с главной (тот же текст, что видит человек).

### Контент для поисковых запросов

На главной добавлена секция «О фамилии Логвинов и об этом архиве» с
индексируемым текстом и FAQ: происхождение фамилии, что открыто публично,
как связаться однофамильцам. Заголовки и description страниц содержат
естественные ключи: «род Логвиновых», «генеалогическое древо Логвиновых»,
«родословная», «хронология», «фамилия Логвинов».

### Для ИИ-агентов (ChatGPT, Perplexity, Claude и др.)

- **`public/llms.txt`** — файл по стандарту [llmstxt.org](https://llmstxt.org):
  краткое описание архива на русском и английском, карта разделов, факты о
  фамилии, контакт хранителя и правила для агентов (не пересказывать
  приватные данные о живых).
- Явное `Allow: /` в robots.txt для всех агентов, включая GPTBot, ClaudeBot,
  PerplexityBot (специальных запретов нет).
- FAQPage JSON-LD и текстовые ответы на типовые вопросы — то, из чего
  ассистенты формируют ответы со ссылкой на сайт.

### Проверки в CI

- `scripts/check-dist-seo.ts` (`npm run test:dist-seo`) — после сборки
  проверяет robots.txt, llms.txt, sitemap, og-image, canonical/OG/JSON-LD
  в каждой HTML-странице. Подключён в `.github/workflows/pages.yml` рядом
  с privacy-сканом.

## Что нужно сделать вручную (однократно)

Индексация не начнётся, пока сайт не добавлен в панели вебмастеров:

1. **Яндекс Вебмастер** — <https://webmaster.yandex.ru>: добавить сайт
   `logvinov-tree.ru`, подтвердить права (DNS-запись или HTML-файл),
   отправить `https://logvinov-tree.ru/sitemap-index.xml` в «Файлы Sitemap».
   Для аудитории из России это главный источник.
2. **Google Search Console** — <https://search.google.com/search-console>:
   добавить домен, подтвердить права (DNS TXT), отправить ту же карту сайта.
   Использовать «Проверка URL» → «Запросить индексирование» для главной.
3. **Bing Webmaster Tools** — <https://www.bing.com/webmasters>: импорт из
   Google Search Console или добавление вручную + отправка sitemap.
   Индекс Bing используется в поиске Perplexity и других ИИ-сервисов —
   это прямой канал попадания в ответы агентов.
4. **IndexNow** (опционально): ключ из Яндекс Вебмастера можно добавить
   как `public/<ключ>.txt`, чтобы изменения индексировались мгновенно.

## После публикации

- Через 2–4 недели проверить в панелях, что все 4 URL проиндексированы
  (`/`, `/tree/`, `/timeline/`, `/gallery/`).
- Проверить сниппеты: по запросам «Логвиновы родословная»,
  «генеалогическое древо Логвиновых», «фамилия Логвинов происхождение».
- Проверить превью ссылки в Telegram/VK (og-image подтягивается из кэша
  мессенджеров; при смене картинки пользоваться их ботами переиндексации).

## Приватность

SEO-материалы содержат только публичные сведения. Имена и годы — публичны
по политике проекта (см. `docs/data-policy.md`); подробные данные о живых
родственниках не попадают ни в мета-теги, ни в JSON-LD, ни в llms.txt.
Контроль: `npm run test:dist-privacy` остаётся обязательным шагом CI.
